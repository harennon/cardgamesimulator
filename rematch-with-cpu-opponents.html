Rematch with CPU opponents — game-over screen

Bug: after a practice game (1 human + N CPUs), the host clicks Rematch, the button looks enabled, but the backend rejects it (NOT_ENOUGH_PLAYERS) because CPU seats hold no socket and are filtered out of the rematch roster. The user only sees "Couldn't start rematch. Try again." forever.

Both options below make the button's state honest. They differ on the product decision: does a practice rematch bring the CPUs back?

Option A — Rematch re-seats the same CPUs

Recommended

A practice rematch stays a practice game: it re-seats the same number of CPU opponents so a solo human can replay instantly (the common 1-human + N-CPU case just works). The panel shows exactly who returns to the table before the click, so there's no surprise. Requires a backend change (createRematch re-seats AI). The two right-hand cells show an optional advanced variant that lets the host retune the CPU count, plus the mixed-table case.

Option B — Rematch stays human-only

The rematch never brings CPUs back (matches the current backend intent: "a rematch is always a fresh human-only game"). Frontend-only fix. The button is only enabled when the connected human roster is ≥ 2 — otherwise it's disabled with a specific explanation instead of a clickable-but-always-fails trap. B1 is the common broken case (solo human) made honest; B2 is a mixed table where a real human-only rematch is viable.
