Tonk Tally Panel — Right-Edge Clipping Fix

On the desktop Tonk board, the running-tally side panel is drawn flush against the viewport edge, so the right-pinned score digits sit underneath the 12px wood-rim ::after overlay. Below: the current bug, then two fix options, side by side on the real board layout with the real TonkTallyPanel markup and design tokens. Use the controls to change simulated width, toggle the rim, and outline the score cells.

Issue #151 · branch lld-142-tonk-tally-panel-clipped-right-edge
Width
12px wood rim (z-index 100, drawn over content) right-pinned score cell (.tonk-tally-row__score)

Current behavior

Bug

The log grid column reaches the viewport's right edge with no inset. Its outer ~12px — where the score value is pinned (grid-template-columns: 18px 1fr auto, only 8px row padding) — is rendered beneath the rim. Watch the last digit of 149 disappear under the wood.

Option A — inset the right column only

Fix

Add padding-right: 12px to .tonk-board__log (and the same one-liner to .game-board__log for Big2). Surgical — touches only the right column. The panel's left border still hugs the table; only the score side pulls in to clear the rim.

Option B — inset all board content from the rim (recommended)

Fix

Add a single padding: 12px to the .tonk-board / .game-board grid container (behind a --board-rim-inset token). Every grid child clears the rim on all four sides in one rule — fixes Tonk tallies AND the Big2 log identically, and also keeps the hand, opponents and actions off the rim. The felt background still bleeds under the rim, so the table look is preserved. Mobile override resets padding to 0 (or to the 4px mobile rim).

Recommendation & notes

  • Option B is recommended. It is one rule per board, expressed as a shared --board-rim-inset: 12px token, and it fixes both games' right panels plus the previously-unnoticed edges (hand/opponents brushing the rim). It matches the acceptance criterion "inset the board grid content from the rim … apply consistently so Big2's right log panel is not clipped either."
  • Option A is the minimal change if we want to touch only the reported symptom. It leaves the left/top/bottom edges hugging the rim (unchanged from today), so it is lower-blast-radius but does not address the same latent issue on the other three sides.
  • Mobile is untouched. At ≤767px the side panel is display: none and the rim shrinks to 4px; both options are scoped to the desktop grid, and the mobile media query keeps the board content edge-to-edge (padding reset to 0 / 4px).
  • Prior PR relevance: the earlier attempt conflicted with PR #159 (LLD 134), which changed the desktop actions row from 64px to auto. That is a vertical/row change; this fix is on the horizontal (column/rim-inset) axis and remains fully relevant — it re-bases cleanly onto the auto actions row shown above.
  • Verified readable at 1024 / 1280 / 1440: toggle "Outline score cells" — the dashed box around 149 stays fully inside the felt, clear of the rim, in both fix options.
