Tonk tally panel — clipped by the table rim

On the desktop Tonk board, .tonk-board is position: fixed; inset: 0 with a grid-template-columns: 1fr 280px layout. A 12px wood rim is painted as a ::after overlay at inset: 0; z-index: 100, while grid children sit at z-index: 1 with no clearance. The right log column holds TonkTallyPanel, whose right-pinned score digits sit ~8px from the edge — inside the 12px rim — so the last digit of a 3-digit tally (e.g. 149) is covered. Below: the broken state, then three fix options. The dashed outline marks each score cell so you can see exactly where the digit lands relative to the rim.

Board width:

Current — broken

clipped

The tally panel reaches the viewport edge; the rim overlay covers its rightmost ~12px. Watch the 149 and 132 score digits — their right edge disappears under the wood band.

Symptom: right-pinned score values (and the far end of the progress bars) render underneath the rim.

Fix options

3 approaches

All three keep the rim visually identical. They differ in where the clearance is added.

Option A — inset the whole board grid

recommended

Add padding: 12px to .tonk-board (a --board-rim token). Every grid cell now sits inside the rim, not under it — fixes the tally panel and any future edge content (Big2 log, hand edges) in one line.

149 and the bars are fully clear of the rim. Consistent for Big2 too.

Option B — pad only the right column

targeted

Add padding-right: 12px to the log grid cell only. Minimal blast radius, but the fix must be duplicated per edge (right log here; would also need left/bottom if those ever clip).

Tally content clears the rim; rest of board unchanged.

Option C — widen panel's inner padding

local

Bump TonkTallyPanel's right padding by 12px. Change lives entirely in the panel, but the panel's left border still touches the edge (harmless) and it does not help Big2's log.

Score digit clears rim; panel background still meets the wood band.

Reference — same panel, isolated

The tally panel content at full fidelity (no rim), showing the intended reading: rank · name · right-pinned tally, with a loss-line progress bar. This is what must be fully visible.

Second and third rows are near the 150 loss line (amber).

Recommended: Option A. It matches the acceptance criterion literally ("inset the board grid content from the rim … apply consistently so Big2's right log panel is not clipped either"), is a single symmetric change on both boards, and removes the whole class of edge-clipping bugs rather than patching one edge.
