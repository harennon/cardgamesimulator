How to Play — Tonk walkthrough (content-only, #123)

The Tonk walkthrough is a declarative content entry rendered through the exact same shell the Big2 walkthrough uses (WalkthroughModal.vue + WalkthroughScene.vue + GameCard.vue). Every modal below is that real production shell, driven only by a new TONK_WALKTHROUGH step array registered in walkthroughs.ts.

The test of the design: adding Tonk must require zero new rendering components. Both options below satisfy that. They differ only in whether the joker step draws a real card face — which costs one type edit in the content layer (not a renderer).
Two authoring options

Same shell, same 6 steps, same captions. The only difference is how the Jokers step renders. Both are pure content changes.

The Jokers concept lives in caption text and a callout scene. No cards scene ever holds a joker, so nothing in the shell, the scene mapper, or the types is touched. The literal cleanest reading of "declarative, no new UI."

Why this proves "declarative, no new UI"

  • Every step is one of the two scene kinds the shell already renders: the cards scene (a row of real GameCards from static fixtures, with selectedIndices / highlightIndices) or the callout scene (icon + text lines). No new WalkthroughScene branch.
  • Fixtures are static literals, mirroring big2Walkthrough.ts — never live game state (LLD 111 decision 7). This is the live-component-thumbnail approach: real components + hard-coded props, no committed PNGs.
  • The (?) FAB is unchanged. HelpCluster.vue already resolves getWalkthrough(currentGameType); registering WALKTHROUGHS.tonk makes the FAB open the Tonk walkthrough automatically whenever the current game type is Tonk. No entrypoint / FAB code change.
  • Option A vs B is the only decision. A keeps the joker in text (zero type edits). B widens the scene fixture type by one union so a real joker card renders — a content-layer type edit, still not a new rendering component. If either option needed a new WalkthroughScene branch, the foundation shell would be wrong; neither does.
