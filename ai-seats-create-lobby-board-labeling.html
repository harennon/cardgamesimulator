AI seats: create-game, lobby & board labeling

A registered host adds N AI opponents at create time; the game starts with 1 human + N CPU seats (backend LLD 118). Everywhere a bot appears — the lobby roster and the in-game opponent seats — it is labeled distinctly from humans via one shared badge atom. Toggle the two labeling directions below; every surface updates together so you can judge them as a system, not in isolation.

Labeling direction
CPU  AI seat — server-driven, excluded from stats
You (host)  the human — always ≥ 1, enforced by the backend
Surface 1 / 3

Create a game — add AI opponents

A new AI opponents stepper sits directly under Players. It is bounded by the remaining seats (maxPlayers − 1 human) so the host can never over-fill the table. A live seat-composition strip shows exactly who will be dealt in. The field only renders for a registered host (guests can't create games). When AI count is 0, the form is byte-for-byte the current form — human-only flows are visually unchanged.

Surface 2 / 3

Lobby — bots labeled in the roster

Each seat that came from an AI slot renders the shared badge inline after the name. The host reads the roster top-to-bottom and instantly tells who's a person waiting to be joined vs. a bot that's already locked in. Requires surfacing an isAi flag on PlayerPublicInfo (derived server-side from gameConfig.aiPlayerIds).
