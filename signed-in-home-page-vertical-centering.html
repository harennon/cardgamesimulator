Signed-in Home — Vertical Centering & Overflow Fix

The signed-in home overflows the viewport and sits above true center. Cause: .flow-page keeps min-height: 100vh even when it is a flex child beneath the nav, so .app-shell = nav (~49px) + 100vh > viewport. The frames below render the real app-shell → nav + flow-page structure inside a fixed "device" so you can see the stray scrollbar and the off-center content. Toggle the fix strategy to compare. A second, minor fix makes the secondary action button match the primary width.

What you are comparing

Before — .flow-page { min-height: 100vh }. The shell is taller than the screen by ~one nav height, so a scrollbar appears and the content centers within the 100vh box (which is pushed down by the nav), reading as off-center / pushed up against the visible area.

After · A (recommended) — .flow-page { flex: 1; min-height: 0 }. The column flex in .app-shell hands the leftover height (viewport − nav) to the flow-page, which then centers content in exactly the visible area. No magic numbers; resilient to nav height changes (font load, wrapping).

After · B — .flow-page { min-height: calc(100vh − navHeight) }. Works, but hard-codes the nav height; if the nav reflows (font load, narrow wrap, future nav content) the number drifts and the bug can creep back.

Button width fix — the signed-out auth prompt's .btn-secondary ("Sign Up") is inline-block with no width, so it shrinks to its text inside the centered flex column, appearing narrower than the full-width primary. Fix: force action buttons (.home__btn) to width: 100% in both the signed-in actions and the signed-out auth prompt so both buttons share the 300px column width.
