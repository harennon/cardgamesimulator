Interaction model & downscale (summary)

Three entry points, one pipeline. File picker (click zone or open native dialog), drag-and-drop onto the modal, and clipboard paste all feed the same addFiles(FileList) handler → validate type/count → downscale via an offscreen <canvas> (longest edge capped, e.g. 1600px, re-encoded at ~0.8 quality) → push a preview object with an object-URL thumbnail.
Deferred upload. Files are held in memory until Submit. On Submit the modal first POSTs the feedback row, then uploads each downscaled blob to /api/feedback/:id/attachments as base64 (the LLD-150 contract), tracking per-file queued → uploading → done | error. A description-only submit skips the attachment step entirely.
Errors never lose text. Type / size / count rejections and per-file upload failures render inline; the description textarea and other thumbnails are preserved, and the user can retry or remove and resubmit.
