Lifetime Stats — per game type

The /stats route. The backend GET /stats returns { userId, games: GameStatsEntry[] } — one entry per game type the player has actually played. Three layout directions for the per-game breakdown, each with the four real states.

Why per-game-type matters (not just cosmetic): Big 2 score is higher-is-better (an achievement). Tonk score is lower-is-better (a penalty), so its meaningful headline is average score (lower = stronger), not a cumulative total. A single combined "win rate / total score" hero would be misleading. Each direction adapts the headline stat per game type.

State
A Game Cards

One felt panel per game type, styled like a playing card (corner pip, serif index). Each card leads with a game-appropriate headline: Big 2 → Win Rate; Tonk → Avg. Score. The smaller grid carries the shared counters. Reads top-to-bottom; ideal while there are only a couple of game types. Closest evolution of the previously approved single-panel mockup — it just repeats the panel per game with a game-aware hero.

B Stat Ledger

A single tally sheet — one row per game type. Shared columns (Played / Wins / Losses / Win Rate) line up for instant cross-game comparison, and a final Headline column shows the per-game signature stat (Big 2: Avg Score ↑ · Tonk: Avg Score ↓). Densest option; scales cleanly as the game roster grows. Collapses to stacked rows on mobile.
