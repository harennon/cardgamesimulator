Tonk desktop action buttons — clipped at bottom of screen

On desktop, the Tonk board uses a fixed grid grid-template-rows: 80px 1fr 220px 64px with overflow: hidden. On the local player's turn the Tonk action panel is a two-line column (phase stepper / turn pill + button row), needing roughly ~102px — well over the 64px row. The buttons overflow below the viewport bottom and are clipped, so the Discard / Draw / Take-discard / Call-TONK buttons cannot be seen or clicked. Big2's panel is a single ~44px button row and fits. Frames are rendered at 0.5× scale of common desktop viewport heights.

Fix A

Taller fixed actions row + a Tonk-specific row height

Raise the actions grid row to a fixed height that fits the two-line Tonk panel plus the error row — introduce a --tonk-actions-height token (e.g. 116px) applied only on the Tonk board's desktop grid; Big2 keeps its 64px row. Smallest, most explicit change. Trade-off: the 1fr table row loses ~52px of height and the number is a magic constant that must be re-checked if the panel ever grows a third line. Shown with the error row present (worst case) to prove it still fits.

Fix B

Auto-height actions row — the panel sizes itself, the table flexes

RECOMMENDED

Change the Tonk desktop grid's last row from a fixed 64px to auto (and let the table's 1fr row absorb the difference). The panel is always exactly as tall as its content — one line, two lines, or two lines + error — with no magic number to maintain and no clipping at any viewport height or any future third line. Because the panel stops stretching to fill a fixed row, the button row also sits tighter and more intentional instead of floating in dead space. Big2's grid is untouched (still 64px). This is the most robust and the least likely to regress. Shown across all three states.

Fix C

Floating overlay panel — decoupled from the grid entirely

Lift the action panel out of the grid flow and pin it as a position: absolute floating card centered near the bottom of the felt, above the wood rim. The grid rows are untouched (Big2 unaffected), and the panel can be any height because it no longer lives in a fixed track — it floats over the table. Most flexible, gives the panel visual prominence. Trade-offs: it overlaps the hand/table area and needs a z-index and a reserved bottom margin so it never covers the hand row; a bigger structural departure from the current footer-bar convention shared with Big2.

Option What changes Pros Cons Big2
A — Taller fixed row Tonk desktop grid last row 64px→~116px via a --tonk-actions-height token Tiny, explicit, obvious diff Magic number; must re-check if panel grows; steals ~52px from the table row on short screens Unchanged (64px)
B — Auto-height row REC Tonk desktop grid last row 64px→auto; table 1fr absorbs it Self-sizing; no magic number; never clips (1/2 lines + error); tighter button row Actions height varies slightly by state (acceptable — footer is at the edge) Unchanged (64px)
C — Floating overlay Panel becomes position: absolute, pinned above the felt; grid row emptied Any height; prominent; grid fully decoupled Overlaps hand/table; z-index + reserved margin; departs from Big2's shared footer pattern Unchanged

All three keep Big2's ActionPanel.vue and its 64px row byte-for-byte unchanged, and none touch the mobile --mobile-actions-height rules. Recommendation: Fix B — it removes the fixed-height mismatch at the root, tolerates the error row and any future panel line without a re-tuned constant, and is the smallest conceptual change that cannot silently regress.
