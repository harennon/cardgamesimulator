Game Over Screen Delay — Final Cards Visibility

Problem: When a player wins, the UI instantly swaps from game board to game over screen. Players never see the winning cards. This removes the climactic moment.

Solution: Introduce a 5-second "victory moment" intermediate state. The game board remains visible (dimmed) while the winning play is highlighted. A countdown + button lets users proceed to full results whenever ready. Two directions explored below.

Interaction model: After the final play arrives via game:state with status: "COMPLETED", the frontend enters a GAME_ENDING display state (frontend-only, not a server state). After 5 seconds OR user click, it transitions to the full GameOverView.
Option A — Center Spotlight Overlay
The game board stays fully visible but darkened via a radial vignette. The winning play appears center-screen at large scale with a gold glow. A ring countdown timer shows seconds remaining. "View Results" button is immediately available. This is the dramatic, cinematic option. The board context (who has what cards remaining) stays visible through the dim overlay.

Component Architecture
GameView.vue (modified) - New computed: displayPhase — 'IN_PROGRESS' | 'GAME_ENDING' | 'COMPLETED' - When status transitions to COMPLETED, displayPhase becomes 'GAME_ENDING' - After 5s OR user click, displayPhase becomes 'COMPLETED' (shows GameOverView) - Template: show GameBoard when displayPhase is IN_PROGRESS or GAME_ENDING - Template: show VictoryOverlay when displayPhase is GAME_ENDING - Template: show GameOverView when displayPhase is COMPLETED VictoryOverlay.vue (NEW component) Props: { winnerName: string, winningCards: Card[], handType: string, countdownSeconds: number // starts at 5, ticks down } Events: { continue: void // user clicked "View Results" } Layout: position: absolute, inset: 0, z-index: 50 State: internal countdown ref (ticked by setInterval) Animation: CSS keyframes for entrance (no JS animation libs) useGameEndTransition (NEW composable) Input: status ref from useGameState Returns: { displayPhase: Ref<'IN_PROGRESS' | 'GAME_ENDING' | 'COMPLETED'>, countdown: Ref<number>, skipToResults: () => void } Behavior: - Watches status; when it changes to 'COMPLETED', sets displayPhase to 'GAME_ENDING' - Starts 5s countdown (setInterval, 1s ticks) - When countdown hits 0 OR skipToResults() called, sets displayPhase to 'COMPLETED' - Cleans up interval on unmount Data flow: Server emits game:state with status='COMPLETED' and winner field set → useGameState updates status ref to 'COMPLETED' → useGameEndTransition detects change, holds in GAME_ENDING for 5s → VictoryOverlay reads final gameState.lastPlay for winning cards → User clicks or timer expires → displayPhase = 'COMPLETED' → GameOverView renders (existing component, unchanged)
State Management
Key insight: The server status is still 'COMPLETED'. The GAME_ENDING state is purely a frontend display concern. No backend changes needed. gameState — already contains all needed data at COMPLETED time: - gameState.winner → winner's playerId - gameState.gameSpecificPublicState.lastPlay → the winning cards - gameState.players → displayName lookup - gameState.scores → for Option B panel preview No new WebSocket events needed. The existing game:state event with status='COMPLETED' already carries the lastPlay and winner fields. Edge cases handled: - User refreshes during GAME_ENDING → gameState arrives as COMPLETED, displayPhase starts at GAME_ENDING again (countdown restarts) - Multiple game:state events → ignored once in GAME_ENDING/COMPLETED - Spectators → same overlay, same behavior - prefers-reduced-motion → skip animations, still show 5s delay
CSS Layout Strategy
VictoryOverlay positioning: - position: absolute; inset: 0 (fills GameBoard parent) - GameBoard already has position: fixed; overflow: hidden - Overlay layers above all board content via z-index: 50 Option A layout: - Flexbox column, centered (align-items: center; justify-content: center) - Cards row: flexbox with gap - Countdown + button: flex column below cards Option B layout: - Flex column with justify-content: space-between - Top: banner (absolute top) - Middle: spotlight cards (absolute center) - Bottom: panel (absolute bottom, slides up) - Panel interior: CSS Grid for scores table Responsive (mobile): - Cards use --card-play-width/height tokens (already responsive) - Button: min-height 48px for touch - Option B panel height: auto with max-height: 50vh - No structural layout changes needed — both options scale naturally
