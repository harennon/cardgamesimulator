Join Game — Mobile Scroll Fix

The /join-game form has almost no content, yet it scrolls on mobile. Root cause: two stacked full-viewport-height containers — .app-shell (min-height: 100vh) holds the nav bar and a .flow-page that is also min-height: 100vh. Document height becomes nav + 100vh, which always overflows by the nav's height; on mobile 100vh also includes the area behind the URL/toolbar chrome, making the overflow worse. The content does not change — only the sizing strategy of .flow-page. Below are the current (broken) behavior and two fix options. The phone frames have a fixed visible-viewport height: if the inner screen scrolls, the bug is present.

Recommended Option A

Flex-fill: .flow-page fills remaining space

Let the existing flex column do the work. .app-shell is already display: flex; flex-direction: column at min-height: 100vh. Give .flow-page flex: 1; min-height: 0 so it consumes exactly the space left after the nav — no second viewport unit, no double-counting, no nav-height math to maintain. Pairing .app-shell with min-height: 100dvh makes the whole shell respect the dynamic mobile viewport (excludes URL chrome). Desktop centering is unchanged because the flow-page still centers its card and now fills the full height.

Option B

Calc-subtract: min-height: calc(100dvh − navHeight)

Keep .flow-page self-sizing, but subtract the nav so the two heights stop adding up. Use a --nav-height variable and 100dvh for mobile-safe sizing: min-height: calc(100dvh − var(--nav-height)). This works without relying on the parent flex context — useful if a flow screen is ever rendered outside .app-shell — but it reintroduces a magic number that must track the real nav height (the nav uses 12px padding + content, so the variable has to be kept in sync). Visually identical to Option A.

Applies to all shared flow screens

  • .flow-page is shared by JoinGameView, LoginView, SignupView, CreateGameView, and HomeView. The fix is a pure CSS change in flows.css (plus one line in App.vue for 100dvh) — no template or component changes.
  • Taller forms (Signup has 3 fields) still grow naturally and scroll only when they genuinely exceed the viewport — which is correct behavior, not the bug.
  • Desktop vertical centering is preserved: the card centers within the full remaining height in both options.
  • 100dvh is supported in all current evergreen mobile browsers; 100vh remains a safe implicit fallback for any legacy engine (the layout just reverts to today's behavior there).
  • Acceptance check: on a 390×844 device with browser chrome, the one-field join form fits with no vertical scroll.
