Bug

Problem: On mobile, border-color updates instantly but transform: translateY doesn't repaint until the next user interaction. The card highlights gold but stays flat — only raising on the next tap.

Root cause: Mobile browsers defer compositing layer updates when triggered inside a touch event. The transition fires but the GPU layer isn't flushed until another interaction forces a repaint.

Fix A — Recommended

Strategy: Pre-promote cards to GPU compositing layers with will-change: transform and translateZ(0). The browser keeps these on the GPU, so translateY changes repaint immediately without waiting for layout.

Trade-off: Slightly higher GPU memory (~13 layers for a full hand). Negligible on modern phones. Uses requestAnimationFrame to batch the class toggle, ensuring the frame is committed.

Fix B — Alternative

Strategy: Replace translateY with margin-top on mobile only (@media max-width: 767px). Margin changes trigger layout reflow, which mobile browsers always repaint synchronously.

Trade-off: Layout shift causes sibling cards to reflow (minimal with flex + align-items: flex-end). Slightly less smooth than GPU-composited transforms but 100% reliable across all mobile browsers. Desktop keeps transform for 60fps.
