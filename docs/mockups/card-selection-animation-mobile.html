Card Selection Animation Fix

Issue #24 — Mobile responsiveness improvement

Root Cause Analysis

The current transition uses transition: transform 0.15s ease. The ease timing function (cubic-bezier 0.25, 0.1, 0.25, 1.0) starts with very low velocity — on a small 14px mobile lift, the first ~50ms shows almost no visible movement. This makes the tap feel unresponsive. On desktop the larger 20px lift partially masks this; on mobile the shorter distance amplifies perceived lag.

Recommended

Option A: 80ms ease-out

Sub-100ms feels instant to human perception while retaining a subtle smooth motion. High initial velocity means the card responds immediately.

transition: transform 80ms ease-out;
transform: translateY(-14px);

Alternative

Option B: 150ms ease-out

Same duration, different curve. Ease-out starts at full velocity then decelerates. More visible animation than A but removes the initial lag. Minimal code change (just swap the easing function).

Alternative

Option C: Instant (no animation)

Zero transition on mobile. Maximum responsiveness, trades polish for speed. Desktop retains its current animation. Good for users who prefer pure efficiency.

Implementation Scope (all options)
  • Add --card-select-duration and --card-select-easing CSS custom properties to :root in game-variables.css
  • Override values inside the existing @media (max-width: 767px) block
  • Update GameCard.vue transition shorthand to reference the new variables
  • Add @media (prefers-reduced-motion: reduce) override setting duration to 0ms
  • No component logic changes, no new files, no prop changes — pure CSS token update
