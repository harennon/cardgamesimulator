AI Opponent Naming & Avatars

Polish layer for practice-game bots (#136, sub-issue 3 of #127). Turns the placeholder CPU 1 / CPU 2 seats into recognizable characters — friendly stable names plus an optional avatar — across every surface a bot appears on. All game logic, turn-driving, and stats exclusion are locked by sub-issues 1 & 2 and untouched here. The blue CPU badge and the gold turn glow established in LLD 120 both remain; this adds identity on top.

Naming scheme (shared by all directions)

A small, curated, alphabetically-ordered name pool replaces CPU 1, CPU 2. Names are assigned by AI-seat ordinal so they are stable and deterministic — the first bot is always the first pool entry, matching how addAiSeats already numbers seats. Card-adjacent, unmistakably non-human, short enough to fit the ellipsized seat labels (≤ 8 chars). The CPU badge still rides alongside so the "this is a bot" signal never depends on recognizing a name.

1. Ace 2. Bishop 3. Cortex 4. Domino 5. Echo 6. Fable 7. Gambit

Pool is sized for the largest table (Tonk, 8 seats → up to 7 bots). Names collide-safe against humans: a human literally named "Ace" still shows no badge/avatar because identity keys off the server-side isAi flag, not the string (LLD 120 Edge Case 10). Only the backend displayName assignment in addAiSeats changes — no new type, no new socket field.

Direction A — Monogram tile

A rounded steel-blue chip with the name's initial, gradient-filled, with a tiny squared corner-tick echoing the CPU badge's squared dot. Cheapest to build (pure CSS, first letter of the name), reads instantly at any size, and never needs an asset. The chip color is the bot signal — warm gold is reserved for turns, so the two never compete.

Direction B — Geometric bot glyph

A single inline-SVG procedural "face" in a dark disc ringed in steel-blue. One shared glyph (not per-name) — the name gives individuality, the glyph gives a consistent species. More characterful and obviously robotic than a monogram; slightly more markup but still asset-free and CSS/SVG-only (no icon font, per the LLD 120 constraint of "no icon fonts / no emoji").

Direction C — Named suit token

A card-suit pip (♠ ♥ ♦ ♣) in a dark square with a tiny "CPU" tick, tying the bots visually to the deck itself. Most on-theme for a card game and the pip cycles per seat, giving each bot a distinct mark. Trade-off: suit pips carry meaning inside Big2/Tonk, so a bot marked "♥" beside real hearts could read as game state on a busy board. Included for completeness; the LLD flags this as the collision risk to weigh.

Create-game convenience — "Fill with AI"

The existing stepper (LLD 120) stays. This adds one optional "Fill remaining seats" shortcut that sets numAiSeats to maxPlayers − 1 in a single tap — the common "I just want to practice solo against a full table" case — plus a small live preview of the bots that will be seated so the host sees the names before creating. Purely a convenience over the stepper; no new request field. This is the only create-game visual change and is why the mockup step is required by the acceptance criteria.

Recommendation

Naming scheme + Direction A (monogram tile), avatar rendered as a small optional variant slot on the existing AiBadge surface (or a sibling AiAvatar atom). Rationale:

  • Cheapest, most robust: pure CSS + the name's first letter. No assets, no icon font (respects the LLD 120 "no emoji / no icon font" rule), scales cleanly board ↔ lobby with a --sm modifier.
  • No game-state ambiguity: unlike Direction C's suit pips, a monogram can never be mistaken for a card on a busy board.
  • Clear identity without stealing the turn signal: steel-blue chip vs gold glow stay in separate lanes (Edge Case 6 verified above).

Scope of change if approved: (1) backend addAiSeats name pool instead of "CPU N"; (2) new AiAvatar.vue atom (or a variant prop on AiBadge) rendered beside the name in the three surfaces that already gate on isAi; (3) the optional "Fill remaining seats" button + table preview in CreateGameView. No new shared types, no socket-payload change, no game-logic change. The "thinking…" line under an active bot is the pre-existing LLD 120 nice-to-have and can ride along or stay deferred.
