- **LLD 011: Lock down `game_history` on prod (SECURITY: revoke stray anon/authenticated writes + enable RLS) and unblock the drift gate**
  - `supabase/migrations/011_lock_down_game_history.sql` — new forward migration. `REVOKE INSERT, UPDATE, DELETE ON game_history FROM anon` **and** `FROM authenticated` (the 008 idiom, extended to `authenticated`; SELECT left intact; REVOKE of an absent grant is a no-op on fresh DBs), then `ALTER TABLE game_history ENABLE ROW LEVEL SECURITY` + a `game_history_select_own` SELECT-own-rows policy (`USING (auth.uid() = user_id)`, mirroring `player_stats` in 002) guarded by a `DO $$ … IF NOT EXISTS (SELECT 1 FROM pg_policies WHERE schemaname = current_schema() …) …` block. Closes a live prod exposure: prod carried TypeORM-era default-privilege write grants on `game_history` with no RLS, so an anon-key holder could forge/delete other users' history via PostgREST. `service_role` (backend) is untouched — retains `GRANT ALL`, bypasses RLS — so history inserts / `get_windowed_stats` are unaffected. The `current_schema()` guard was VERIFIED idempotent against the local Supabase stack.
  - `supabase/migrations/postconditions/011_lock_down_game_history.postcondition.sql` — asserts RLS is ENABLED (`pg_class.relrowsecurity`), a SELECT-own-rows policy exists (shape-based: `cmd='SELECT'` + `qual ILIKE '%user_id%'`, never by policy name), and the grant set is `anon`/`authenticated` SELECT-only, `service_role` full.
  - `supabase/migrations/postconditions/010_create_game_history.postcondition.sql` — backfilled with the same RLS-enabled + SELECT-policy assertions (cumulative post-011 state; documented in the header) so the missing-RLS class cannot silently regress even if 011 is reverted. Both migrations retain 1:1 post-condition coverage.
  - `supabase/migrations/expected-diff.allowlist.json` + `scripts/fixtures/clean-diff.json` — Phase-0 gate choreography (kept in lockstep): `expectedPending`/`pending` reconciled from the applied `010` to pending `011`; the six stray `grant:{anon,authenticated}:game_history:{INSERT,UPDATE,DELETE}` residual grants (that 011 REVOKEs) acknowledged TRANSIENTLY (issue #176) and mirrored into `clean-diff.json.objects` so they are "used"; 011's own ENABLE RLS + CREATE POLICY are NOT acknowledged (they self-attribute to pending 011 under LLD 77b and drop as benign). - **LLD 77b: Linked-prod drift adapter now classifies RLS + policy statements (was fail-closed F3)**

- **LLD 127: AI opponent move policy — smarter play beyond auto-timeout heuristic**
  - `src/backend/engine/game-engine.ts` — added `getAiMoveAction(state)` to the `GameEngine` interface (parallel to `getAutoTimeoutAction`; same null contract).
  - `src/backend/engine/big2/ai-policy.ts` — new pure policy module: `chooseBig2Move(myHand, pub, playerId)` with `Big2PolicyView`. Strategy: first-play sheds lowest card in a pair/5-combo if possible; free-play leads cheapest combo of largest size, holding high singletons (never leads a `2`/`A` while lower cards exist); follow-play beats lastPlay when close to out, the beat is cheap (≤J), or it would win the trick — otherwise passes to conserve high cards. Combo-preservation guard prevents breaking pairs to lead a single when a true singleton is available.
  - `src/backend/engine/big2/big2-engine.ts` — `Big2Engine.getAiMoveAction` builds `Big2PolicyView` from `Big2State`, delegates to `chooseBig2Move`, and falls back to `getAutoTimeoutAction` if the policy somehow returns an illegal action.
  - `src/backend/engine/tonk/ai-policy.ts` — new pure policy module: `chooseTonkMove(myHand, pub, playerId)` with `TonkPolicyView` and `TONK_CALL_THRESHOLD = 10`. Discard phase: calls TONK when gate is open and `handValue ≤ 10`; otherwise discards the full same-rank group with the highest total value (dumping pairs removes more points). Draw phase: draws from discard only when the drawable card is strictly cheaper than the cheapest card held (never breaks a joker advantage); otherwise draws from stock.
  - `src/backend/engine/tonk/tonk-engine.ts` — `TonkEngine.getAiMoveAction` builds `TonkPolicyView` from `TonkState`, delegates to `chooseTonkMove`.
  - `src/backend/websocket/socketHandler.ts` — `autoPlayAbandoned` now branches on `isAiSeat`: AI seats call `engine.getAiMoveAction`, abandoned humans call `engine.getAutoTimeoutAction` (unchanged). `handleTimerExpired` is untouched.
