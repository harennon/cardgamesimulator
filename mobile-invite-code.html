Component Architecture

GameLobbyView.vue (modified)
  Props: { gameId: string, players, maxPlayers, isHost, actionPending }
  New computed: shortCode — first 8 chars of gameId, uppercased, grouped as "XXXX XXXX"
  New method: copyGameCode() — writes shortCode (no spaces) to clipboard, shows toast
  Existing method: copyInviteLink() — unchanged, demoted to secondary button

  Template change:
    Replace .lobby__invite with .invite-section:
      span.invite-label        — "Room Code"
      .invite-code             — tap target (code text + copy icon SVG)
      span.invite-toast        — "Copied to clipboard" (visible 2s)
      button.invite-link-btn   — "Copy Full Invite Link" (secondary)

Layout strategy:
  Flexbox column within lobby__panel (already is).
  invite-section is full-width within panel.
  On mobile (<767px), lobby__panel padding reduces to 24px 18px.
  Code font-size scales down slightly on very narrow screens (min 1.3rem).

State management:
  codeCopied: ref<boolean> — drives toast + icon swap
  setTimeout resets codeCopied after 2000ms
  No new composables — purely local component state.

Interaction model:
  1. User taps .invite-code → copyGameCode() fires
  2. Icon swaps from clipboard to checkmark (CSS transition)
  3. Toast appears below code ("Copied to clipboard")
  4. After 2s, icon and toast revert
  5. "Copy Full Invite Link" remains as fallback for sharing the URL

Data flow:
  gameId prop (already passed from GameView parent)
  → computed shortCode derives display string
  → no backend changes needed (UUID first 8 chars are unique enough for verbal sharing)
  → JoinGameView already accepts full gameId as input — users paste/type the short code,
    backend finds game by prefix match OR we require full ID (decision needed)
