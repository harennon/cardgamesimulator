Issue #24: Card Selection Animation Feels Slow on Mobile

Problem: The translateY transition on card selection feels sluggish on mobile (Firefox Android, 395x804 viewport).

Current CSS: transition: transform 0.15s ease on .card
Root causes:
1. ease timing function decelerates at the end — the last few pixels feel slow
2. No will-change: transform hint — mobile browsers may not GPU-accelerate
3. 150ms is long enough to perceive on touch (touch interaction expects near-instant feedback)
4. No prefers-reduced-motion media query — accessibility gap

Option A: Current Behavior (baseline)

transition: transform 0.15s ease — the existing production code. Perceptibly smooth on desktop, but the deceleration at the end of ease makes the last 3-4px of lift feel dragged out on mobile touch.

/* GameCard.vue — no change */
transition: transform 0.15s ease, box-shadow 0.15s ease, border-color 0.15s ease;

Option B: Faster + ease-out (recommended)

transition: transform 0.08s ease-out + will-change: transform. 80ms is below the perception threshold for "animation" — it feels like instant feedback with just enough motion to communicate the state change. ease-out starts fast and decelerates gently, which feels responsive. will-change ensures GPU layer promotion.

- transition: transform 0.15s ease, box-shadow 0.15s ease, border-color 0.15s ease;
+ transition: transform 0.08s ease-out, box-shadow 0.08s ease-out, border-color 0.08s ease-out;
+ will-change: transform;

Additional Changes (all options)

Regardless of which animation timing is chosen, the following changes should also be applied:

/* game-variables.css — add prefers-reduced-motion override */
+ @media (prefers-reduced-motion: reduce) {
+ :root {
+ --card-selected-lift: -14px; /* keep the lift visible */
+ }
+ }

/* GameCard.vue — add reduced motion */
+ @media (prefers-reduced-motion: reduce) {
+ .card { transition: none; }
+ }

/* GameCard.vue — add touch-action for tap performance */
+ .card--interactive {
+ touch-action: manipulation;
+ -webkit-tap-highlight-color: transparent;
+ }
Recommendation: Option B (0.08s ease-out + will-change).

Rationale: 80ms is fast enough that the card feels instantly responsive on touch, while retaining just enough motion to communicate the state change visually. The ease-out curve front-loads the movement so the user sees the card start lifting immediately. Combined with will-change: transform for GPU compositing and touch-action: manipulation to eliminate tap delay, this should completely resolve the perceived sluggishness on mobile Firefox.

Option C (instant) is the safest fallback if 80ms still feels slow on low-end devices, but loses the subtle motion quality.
  • will-change: transform promotes the card to its own compositor layer — GPU-accelerated
  • touch-action: manipulation removes the 300ms tap delay on mobile browsers
  • -webkit-tap-highlight-color: transparent removes the blue flash on Android Chrome/Firefox
  • prefers-reduced-motion: reduce respects user accessibility settings
  • Desktop transition unchanged (0.15s ease) — only mobile gets faster timing via media query, OR apply globally since 80ms still looks smooth on desktop
